# 合成案例｜内容与事实契约

## PPT Brief

| 维度 | 已确认内容 |
| --- | --- |
| PPT 目的 | 向管理层说明一套通用的数据服务建设路径 |
| 受众 | 业务与数据管理人员，不要求掌握实现细节 |
| 核心目标 | 让受众理解需求、产品、交付与场景之间的关系 |
| 内容来源 | 本文件中的合成信息；不存在外部真实业务事实 |
| 篇幅与时间 | 4 页，约 5 分钟 |
| 表达风格 | 管理型、结论先行、蓝白简洁风格 |
| 视觉约束 | 16:9；全部文字和形状保持 PowerPoint 原生可编辑 |

## 事实边界

本案例只使用以下合成结论：

1. 服务规划从业务需求出发，经产品化后进入场景交付。
2. 建设过程分为需求澄清、产品沉淀、交付运营和持续评价四步。
3. 一个产品可以支撑多个场景，一个场景也可以组合多个产品。
4. 页面不展示真实企业名称、项目名称、金额、产量或经营指标。

## 内容结构

1. 封面：说明主题和使用目的。
2. 总体认识：用三张卡片概括需求、产品和交付。
3. 建设路径：展示四步闭环。
4. 场景映射：展示多对多关系与治理要求。

## 来源

- 本案例为仓库内合成演示材料。
