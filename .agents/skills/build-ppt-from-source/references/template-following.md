# 参考模板落实约定

当用户提供参考 PPT/PPTX、公司模板或模板包时读取本文。目标是把模板转成
可执行的版式约束，而不是仅凭印象选择相近配色。

## 模板证据优先级

1. 模板包中的 `README.md`、`template.json` 或其他机器可读规范。
2. 可编辑参考 PPTX 中的页面尺寸、母版、字体、颜色、形状和对象坐标。
3. 逐页预览图或总览图。
4. 用户的文字描述。

证据冲突时先报告差异并让用户确认。预览图片无法被当前模型可靠读取时，
只依据机器可读信息形成样式契约，并明确视觉还原需要用户核验。

## 构建前形成样式契约

在 storyboard 全局版式契约中记录：

- 画布比例和正文安全区；
- 标题、正文、卡片、表格、页脚的字体层级；
- 主色、强调色、背景色、边框色；
- 页眉、Logo、页码和品牌线位置；
- 可复用页面类型及其几何结构；
- 必须保留和不得作为正文继承的模板元素；
- 无法确认的视觉信息及人工核验点。

只有样式契约确认后才写 `build.mjs`。

## 实现选择

- 模板允许复用母版或页面时，优先保留原生模板结构并替换内容。
- PptxGenJS 无法无损继承模板对象时，把已确认的样式契约实现为 token 和 helper。
- 固定公司模板应维护独立模板包，不把具体坐标散落在业务页面函数中。
- 模板页面中的示例标题、占位文案和汇报说明不自动成为业务内容。
- 没有可靠模板证据时生成保守基础版，并把视觉还原标记为待确认，不声称严格复刻。

## QA

默认构建仍采用结构验证。用户明确要求视觉 QA 时，逐页检查字体替换、换行、
裁切、重叠、对象层级、Logo、页码和页面节奏。人工确认的修复先同步到 storyboard
和 builder，再重新生成 `.generated.pptx`。
